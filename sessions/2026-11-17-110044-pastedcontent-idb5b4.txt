  ## 1. Make ingestion atomic (rag.py `ingest_company`, database.py)
  Right now `db.clear_company_data()` runs BEFORE extraction. If Gemini is
  down, each page's extraction failure is caught, zero people get saved, and
  the previous good data is wiped, but the UI still says "Collection complete".
  - Do all collection, extraction and resolution in memory first. At the end,
  clear the old data and write the new people and sources inside ONE SQLite
  transaction.
  - If every extraction attempt failed (`report["extraction_failures"]` covers
  all candidate pages), raise an error and leave the existing data untouched.
  - Set `scraped_at` only when the write succeeds.

  ## 2. Fix the roster rule that drops VPs and heads (entities.py
  `resolve_people`, rag.py `_weakly_supported` / `_corroborate`)
  When a live company page lists 3 or more people (`has_roster`), everyone not
  on a live company page is excluded with `REASON_NOT_ON_ROSTER`. The reason
  text says "and no recent evidence", but no date is checked, and
  `STALE_AFTER_DAYS = 730` is never used. Leadership pages usually list only
  the C-suite, so VPs and heads found via news, LinkedIn or SEC filings are all
  dropped.
  - Only exclude a person under this rule if their newest evidence date is
  older than `STALE_AFTER_DAYS` (or has no date) AND none of their sources is
  tier 1 (company domain or .gov).
  - Corroboration currently searches for people excluded by this rule, but the
  new pages can never satisfy it. After the fix, check that corroboration
  actually helps. If it doesn't, simplify or remove it.

  ## 3. Collect location and profile data (rag.py `Leader`, `EXTRACT_PROMPT`,
  database.py, views.py)
  "Where is their CEO based?" is one of the required example questions, and the
  brief asks for "public profile data", but the schema has no field for
  either.
  - Add `location` (professional base only, never a home address),
  `profile_url` (e.g. their public LinkedIn) and `bio` (one short sentence) to
  `Leader`. Leave a field "" if the page doesn't state it. Never guess.
  - Store them on `leaders` and choose values during `_consolidate`: prefer
  tier-1 sources, then the newest.
  - Add them to the PEOPLE lines in `build_context` and to the table in
  views.py.

  ## 4. Remove code the project doesn't need (database.py, entities.py, app.py,
  views.py)
  - Delete the migration machinery: `_ADDED_COLUMNS`, `_DROPPED_COLUMNS`, the

  - Remove the stray string before `crawl_company_site` in scraper.py.

  ## 5. Fix the promotion bug (entities.py `_supersedes`)
  Every record from one page shares the same date, and a former role cancels a
  current one when its role words are a subset and its date is `>=`. So in
  "formerly VP of Product, now SVP of Product", the SVP claim gets cancelled.
  Require the former record to be strictly newer OR from a different source
  URL.
